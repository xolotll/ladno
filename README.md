# Ладно — PWA для личного бюджета

«Ладно» — Flutter-приложение для учёта личного бюджета, подготовленное для запуска в браузере и установки на iPhone как веб-приложение (PWA).

## Что умеет приложение

- Главный экран с месячным бюджетом, остатком и прогрессом.
- Категории расходов и месячные лимиты.
- Добавление, редактирование и удаление расходов.
- Статистика и настройки валюты/бюджета.
- Русский интерфейс и адаптация под мобильный экран.
- Локальное сохранение данных в браузере через `shared_preferences` (на web — браузерное хранилище).
- PWA manifest, иконки, standalone-режим и service worker для повторного открытия без сети после первой загрузки.

## Бесплатная публикация через GitHub Pages

Публикация не требует Mac, Xcode, Apple Developer Program или платного хостинга. В бесплатном тарифе GitHub Pages для этого сценария используйте публичный репозиторий. В репозитории находится исходный код приложения, **не ваши личные расходы**: данные бюджета сохраняются локально в браузере и в GitHub не отправляются.

### 1. Подготовьте папку проекта на Windows

1. Распакуйте ZIP в обычную папку, например `C:\Projects\ladno`.
2. Установите GitHub Desktop: https://desktop.github.com/ и войдите в бесплатный GitHub-аккаунт: https://github.com/.

### 2. Загрузите проект на GitHub

1. В GitHub Desktop выберите **File → Add local repository** и укажите папку `ladno`.
2. Если GitHub Desktop предложит создать репозиторий, подтвердите создание.
3. Нажмите **Publish repository**.
4. Для бесплатного GitHub Pages оставьте репозиторий **Public** и опубликуйте его.

Публичным будет только код приложения. Данные, которые вы внесёте в «Ладно», хранятся в браузере на вашем устройстве.

### 3. Включите автоматическую публикацию

1. Откройте репозиторий на GitHub в браузере.
2. Перейдите в **Settings → Pages**.
3. В разделе **Build and deployment** выберите **GitHub Actions** как Source.
4. Откройте вкладку **Actions**. Workflow `Build and deploy Ladno PWA` запустится после отправки кода в ветку `main`.
5. Дождитесь зелёной галочки у workflow. Первый запуск обычно занимает несколько минут.
6. Адрес будет таким: `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/`. Точный URL также появится в **Settings → Pages**.

При каждом последующем push в `main` сайт будет пересобираться автоматически.

## Установка на iPhone

1. Откройте опубликованный HTTPS-адрес **именно в Safari** на iPhone.
2. Нажмите кнопку **Поделиться** (квадрат со стрелкой вверх).
3. Прокрутите список действий и выберите **На экран «Домой»** / **Add to Home Screen**.
4. Если доступен переключатель **Открывать как веб-приложение** / **Open as Web App**, включите его.
5. Нажмите **Добавить**.
6. Запускайте «Ладно» с появившейся иконки на домашнем экране.

Для первой загрузки нужен интернет. После первой загрузки service worker кэширует приложение и уже загруженные ресурсы; доступность всех функций офлайн зависит от того, какие файлы успели закэшироваться.

## Проверка, что открыт именно PWA-проект

В PWA-версии точка входа `lib/main.dart` создаёт `BudgetRepository` напрямую. Хранение реализовано через `shared_preferences` и браузерное хранилище. В проекте нет SQLite / `sqflite`; файл старой заглушки `app_database.dart` удалён, чтобы не путать его с исходным Android-проектом. Если в консоли появляется `databaseFactory not initialized` или путь `data/local/app_database.dart`, запущена не эта папка проекта (либо IDE использует старый запуск/кэш).

## Локальный запуск / сборка

Нужен Flutter stable SDK. Из корня проекта:

```powershell
flutter doctor -v
flutter pub get
flutter run -d chrome
```

Собрать web-версию локально:

```powershell
flutter build web --release
```

Для GitHub Pages используйте именно workflow из `.github/workflows/deploy.yml`: он задаёт корректный `base-href` для адреса проекта.

## Важные ограничения хранения данных

- Данные хранятся локально в браузере на конкретном устройстве/профиле Safari. Они не синхронизируются между устройствами и не попадают в аккаунт GitHub.
- Очистка данных сайта/истории и данных веб-сайтов в Safari может удалить локальные данные приложения. Не очищайте данные сайта, если в приложении есть важные записи.
- Удаление иконки с домашнего экрана не является резервным копированием. Пока в приложении нет облачной синхронизации или экспорта резервной копии.
- PWA — веб-приложение, а не опубликованное приложение из App Store.

## Проверка проекта

В среде подготовки архива Flutter SDK не установлен, поэтому `flutter pub get`, `flutter analyze`, `flutter test` и `flutter build web` здесь не выполнялись. Архив содержит исходники, PWA-обвязку и workflow автоматической сборки. Фактическая компиляция произойдёт в GitHub Actions; перед установкой дождитесь успешного workflow.
